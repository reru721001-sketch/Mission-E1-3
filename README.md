# Mini NPU Simulator

MAC(Multiply-Accumulate) 연산으로 입력 패턴이 Cross(십자가)인지 X인지 판별하는 Python 콘솔 프로그램입니다.

## 실행 방법

- 필요 환경: Python 3.8 이상 (외부 라이브러리 없음)
- `data.json`은 `main.py`와 같은 폴더에 둡니다.

```
python main.py
```

- `1` 입력: 사용자 입력 모드
  - `1` 직접 입력: 3×3 필터 A, B와 패턴을 한 줄씩 공백으로 구분해 입력
  - `2` 패턴 생성기: 크기 N(3 이상)을 입력하면 필터 A=Cross, B=X가 자동 생성되고, 패턴(Cross 또는 X)을 골라 판정
- `2` 입력: data.json 분석 모드

## 구현 요약

- **데이터 구조**: N×N 표를 "리스트 안의 리스트"로 저장합니다. `grid[i][j]`로 i행 j열 값을 읽고 씁니다. 3×3, 5×5, 13×13, 25×25를 포함해 모든 N을 처리할 수 있습니다.
- **라벨 정규화**: `LABELS` 표로 expected 값 `'+'` → `Cross`, `'x'` → `X`, 필터 키 `'cross'` → `Cross`, `'x'` → `X`로 변환합니다. 출력과 PASS/FAIL 비교는 모두 표준 라벨로 합니다.
- **MAC 연산**: `mac()`이 이중 반복문으로 같은 위치끼리 곱한 값을 `total`에 누적합니다(NumPy 사용 안 함).
- **동점 정책**: `abs(score_a - score_b) < 1e-9`이면 `UNDECIDED`(판정 불가)로 봅니다.
- **스키마 검증**: 패턴 키 `size_N_번호`에서 N을 꺼내 `size_N` 필터를 고릅니다. 그 필터가 없거나 패턴 크기가 N×N이 아니면 그 케이스만 FAIL로 처리하고 사유를 남깁니다. `input`이 빠진 경우처럼 데이터가 깨져 있어도 `try/except`로 잡아 FAIL 처리하므로 프로그램이 멈추지 않습니다.
- **입력 검증(모드 1)**: 한 줄의 숫자 개수가 3개가 아니거나 숫자로 바꿀 수 없으면 안내 문구를 출력하고 그 행렬을 처음부터 다시 입력받습니다.
- **성능 측정**: `time.perf_counter()`로 MAC 함수 호출 구간만 10회 반복 측정해 평균(ms)을 냅니다. 입력, 출력, 파일 읽기 시간은 포함하지 않습니다.
- **보너스(패턴 생성기)**: 크기 N을 받아 N×N 그림을 자동으로 만듭니다.
  - `make_cross(n)`: 가운데 행 또는 가운데 열이면 1, 나머지는 0입니다. (홀수 N일 때 정확한 십자가가 됩니다)
  - `make_x(n)`: 두 대각선(`i == j` 또는 `i + j == n-1`) 위의 칸이면 1, 나머지는 0입니다.
  - 생성한 그림은 모드 1(자동 생성 선택 시)과 성능 분석 표의 측정용 데이터로 다시 사용합니다.

총 테스트 6개 중 통과 3개, 실패 3개입니다.

| 케이스 | Cross 점수 | X 점수 | 판정 | expected | 결과 |
|---|---|---|---|---|---|
| size_5_1 | 0.9 | 0.8999999999999999 | UNDECIDED | X | FAIL |
| size_5_2 | 8.9 | 0.1 | Cross | Cross | PASS |
| size_13_1 | 0.3 | 14.700000000000008 | X | X | PASS |
| size_13_2 | 7.499999999999997 | 7.5 | UNDECIDED | Cross | FAIL |
| size_25_1 | 4.9 | 4.899999999999999 | UNDECIDED | X | FAIL |
| size_25_2 | 52.9 | 0.1 | Cross | Cross | PASS |

### 2. 실패 원인 분석

실패 원인을 세 가지로 나누어 확인했습니다.

- **데이터/스키마 문제가 아님**: 모든 케이스의 키가 `size_N_idx` 형식이고 필터와 패턴 크기도 같습니다. expected의 `'+'`, `'x'`는 정규화로 `Cross`, `X`로 바뀌었기 때문에 라벨 표기가 달라서 생긴 실패는 없습니다. 정규화를 하지 않았다면 `'+'`와 `'Cross'`를 비교하게 되어 정답도 FAIL이 되었을 것입니다.
- **로직 문제가 아님**: 점수 차이가 큰 3개 케이스는 모두 맞게 판정되었습니다. 이것으로 MAC 연산과 비교 방향이 맞다는 것을 확인할 수 있습니다.
- **수치 비교 문제(동점 규칙)**: 실패한 3개 케이스는 모두 두 점수가 사실상 같습니다. 예를 들어 0.9와 0.8999999999999999의 차이는 약 1e-16입니다. 이 값은 실수를 2진수로 정확히 표현할 수 없어서 생기는 부동소수점 오차로, 더하는 순서에 따라 마지막 자리가 달라집니다.
- 단순 `>` 비교를 쓰면 이런 오차만으로 Cross나 X 중 하나가 "우연히" 선택됩니다. 그 결과는 의미 없는 판정입니다. `1e-9` 허용오차 정책은 이 경우를 UNDECIDED로 처리해 판정을 보류합니다.
- 따라서 이 3개의 FAIL은 버그가 아닙니다. "패턴이 두 필터와 똑같이 닮아 구별할 수 없다"는 사실을 정책대로 보고한 결과입니다. 이 케이스의 expected 값은 의미 있는 차이로는 판별할 수 없는 정답입니다.
- 개선이 필요하다면 필터를 바꾸거나(예: 배경에 음수 가중치 부여) 동점일 때 사용할 정책을 별도로 정해야 합니다. epsilon을 지나치게 작게 줄이면 오차가 다시 판정을 좌우하게 되므로 바람직하지 않습니다.

### 3. 시간 복잡도 분석

| 크기 | 평균 시간(ms) | 연산 횟수(N²) |
|---|---|---|
| 3×3 | 0.0006 | 9 |
| 5×5 | 0.0010 | 25 |
| 13×13 | 0.0045 | 169 |
| 25×25 | 0.0163 | 625 |

(측정값은 실행 환경에 따라 달라집니다.)

- MAC 연산은 N×N의 모든 칸에서 곱셈 1번, 덧셈 1번을 하므로 연산 횟수는 N²이고 시간 복잡도는 **O(N²)**입니다.
- 5×5에서 25×25로 가면 연산 횟수는 25배(25 → 625) 늘고, 측정 시간은 약 16배(0.0010 → 0.0163 ms) 늘었습니다. N이 5배 커질 때 시간이 N에 비례(5배)하는 것이 아니라 N²에 가깝게 증가합니다.
- 작은 크기에서 배율이 N²보다 작은 이유는 함수 호출과 반복문 준비 같은 고정 비용이 차지하는 비중이 크기 때문입니다. N이 커질수록 시간은 N²에 비례하는 쪽에 가까워집니다.
- 실제 AI 모델은 수백×수백 크기의 필터를 수천 개 사용하므로 연산량이 N²에 필터 개수를 곱한 만큼 커집니다. 이렇게 단순한 곱셈과 덧셈을 동시에 대량으로 처리하기 위해 병렬 MAC 유닛을 가진 NPU가 필요합니다.
