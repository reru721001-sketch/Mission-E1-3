# Mini NPU Simulator

MAC(Multiply-Accumulate) 연산으로 그림이 십자가(Cross)인지 X인지 판별하는 Python 콘솔 프로그램입니다.

## 1. 실행 방법

- Python 3.8 이상이 필요합니다. 외부 라이브러리는 쓰지 않습니다.
- `data.json`은 `main.py`와 **같은 폴더**에 둡니다.
- 그 폴더에서 아래 명령으로 실행합니다.

```
python main.py
```

**모드 선택**

| 입력 | 모드 | 하는 일 |
|---|---|---|
| `1` | 사용자 입력 | 3×3 필터 A, B와 패턴을 한 줄씩 공백으로 구분해 입력 → 점수, 판정, 연산 시간 출력 |
| `2` | data.json 분석 | data.json의 패턴 6개를 판정하고 정답과 비교해 PASS/FAIL 출력 → 성능 표, 결과 요약 출력 |

모드 1에서 다시 `1`을 고르면 직접 입력, `2`를 고르면 크기 N을 입력해 십자가와 X를 자동으로 만드는 패턴 생성기(보너스)를 씁니다.

## 2. 구현 요약

**라벨 정규화**

data.json은 같은 뜻인데 표기가 제각각입니다. 정답(expected)은 `+` / `x`, 필터 이름은 `cross` / `x`입니다. 컴퓨터는 글자가 하나라도 다르면 다른 것으로 보기 때문에, 그대로 비교하면 정답을 맞혀도 FAIL이 됩니다. 그래서 아래 표로 모두 표준 라벨 `Cross` / `X`로 바꾼 뒤 출력하고 비교합니다.

```python
LABELS = {"+": "Cross", "cross": "Cross", "x": "X"}
```

**MAC 연산**

그림과 필터를 겹쳐 같은 칸끼리 곱하고(Multiply), 그 결과를 계속 더해(Accumulate) 점수를 냅니다. NumPy 없이 이중 반복문으로 직접 구현했습니다. 0과 1로 된 그림이면 둘 다 1인 칸만 점수가 되므로, 점수는 겹치는 칸의 개수입니다. 두 필터 중 점수가 높은 쪽으로 판정합니다.

```python
for i in range(n):          # i = 가로줄(행) 번호
    for j in range(n):      # j = 세로줄(열) 번호
        total += pattern[i][j] * filter_grid[i][j]
```

**동점 처리 정책 (epsilon)**

컴퓨터는 소수를 2진수로 저장하면서 미세한 오차가 생깁니다(예: `0.1 + 0.2 = 0.30000000000000004`). 그래서 두 점수의 차이가 `1e-9`(0.000000001)보다 작으면 동점으로 보고 `UNDECIDED`(판정 불가)로 처리합니다.

```python
if abs(score_a - score_b) < 1e-9:
    return "UNDECIDED"
```

## 3. 결과 리포트

### 3-1. 실패 원인 분석

**실행 결과: 총 6개 / 통과 3개 / 실패 3개**

| 케이스 | Cross 점수 | X 점수 | 판정 | expected | 결과 |
|---|---|---|---|---|---|
| size_5_1 | 0.9 | 0.8999999999999999 | UNDECIDED | X | FAIL |
| size_5_2 | 8.9 | 0.1 | Cross | Cross | PASS |
| size_13_1 | 0.3 | 14.700000000000008 | X | X | PASS |
| size_13_2 | 7.499999999999997 | 7.5 | UNDECIDED | Cross | FAIL |
| size_25_1 | 4.9 | 4.899999999999999 | UNDECIDED | X | FAIL |
| size_25_2 | 52.9 | 0.1 | Cross | Cross | PASS |

실패 원인을 세 가지로 나눠 순서대로 확인했습니다.

| 순서 | 원인 종류 | 확인한 것 | 판단 |
|---|---|---|---|
| 1 | 데이터/스키마 문제 | 모든 패턴이 필터와 크기가 맞고, 라벨은 정규화로 통일됨 | 아님 |
| 2 | 로직 문제 | 점수 차이가 뚜렷한 3개(8.9 vs 0.1 등)는 모두 PASS | 아님 |
| 3 | 수치 비교 문제 | FAIL 3개는 두 점수가 사실상 같음 (차이 약 1e-16) | **원인** |

- 코드가 잘못됐다면 점수 차이가 뚜렷한 케이스도 틀렸어야 합니다. 모두 맞혔으므로 로직은 정상입니다.
- size_5_1의 그림은 1.0으로 된 깔끔한 X입니다. 하지만 data.json의 X 필터는 칸마다 0.1, 십자가 필터 정중앙은 0.9입니다. 그래서 X 필터는 0.1 × 9칸 = 0.9, 십자가 필터는 0.9 × 1칸 = 0.9로 원래 두 점수가 같습니다.
- 그런데 X 점수는 0.1을 9번 더하는 동안 부동소수점 오차가 쌓여 0.8999999999999999가 됐습니다.
- epsilon 없이 그냥 비교하면 0.9 > 0.8999…라서 Cross로 판정합니다. 그림은 X인데 오차가 우연히 승부를 정하는 것입니다.
- epsilon 정책을 적용해 동점(UNDECIDED)으로 판정했고, 이것이 정답 X와 다르므로 FAIL이 됐습니다.
- 따라서 이 3개의 FAIL은 버그가 아니라, 필터가 두 모양을 구별하지 못하는 케이스를 규칙대로 "판정 불가"라고 보고한 결과입니다.
- epsilon을 줄이면 오차가 다시 판정을 좌우하므로 개선 방법이 아닙니다. 필터를 두 모양이 잘 구별되게 바꾸거나, 동점일 때의 규칙을 따로 정해야 합니다.

### 3-2. 시간 복잡도 분석

MAC 계산 부분만 10회 반복해 평균을 냈습니다. 입력, 출력, 파일 읽기 시간은 포함하지 않았습니다. 측정값은 실행할 때마다 조금씩 달라집니다.

| 크기 | 평균 시간(ms) | 연산 횟수(N²) |
|---|---|---|
| 3×3 | 0.0024 | 9 |
| 5×5 | 0.0037 | 25 |
| 13×13 | 0.0167 | 169 |
| 25×25 | 0.0637 | 625 |

- N×N 그림은 칸이 N²개이고 칸마다 곱셈을 한 번씩 하므로, 연산 횟수는 N²입니다. 코드에서는 `for` 안에 `for`가 있는 이중 반복문(N번 × N번)이 근거입니다.
- 5×5에서 25×25로 가면 한 변은 5배, 연산 횟수는 25배(25 → 625) 늘어납니다.
- 측정 시간은 0.0037ms에서 0.0637ms로 약 17배 늘었습니다. 크기(5배)보다 훨씬 많이 늘었으므로, 시간이 연산 횟수(N²)를 따라 늘어난다는 것을 확인했습니다. 이것이 시간 복잡도 **O(N²)**입니다.
- 딱 25배가 아닌 이유는 함수 호출처럼 크기와 상관없이 항상 드는 기본 시간이 섞여 있기 때문입니다. 크기가 작을수록 이 기본 시간의 비중이 커집니다.
